# 使用指南

## 自动接入

将已构建的 `cocos-performance-inspector` 文件夹复制到项目 `extensions` 下，在 Creator 扩展管理器启用后，打开本机浏览器预览即可。已经开着的预览应在首次安装后刷新一次。

无需安装 SDK、编辑场景、添加常驻节点，或复制 Endpoint / Token。插件通过 Creator 浏览器预览的插件脚本入口接入，连接信息由同源预览服务动态提供。切换场景不会停止采集。

预览打开后，从插件会话列表选择在线会话。每次页面重载或应用新的采集设置会开始新会话；旧会话可继续查看与导出。最多保留五个会话。

从 1.0 版升级时，自动入口识别 `PerformanceInspectorBootstrap`，临时接管它的预览启动逻辑并停止它已拥有的采集器，避免旧挂点重复采集。项目文件保持原样。应用了其他自定义手动启动代码的项目，应避免另行启动第二套采集器。

## 设置

在“自动接入与采集设置”中配置：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 采样间隔 | 1000 ms | 允许 250–10000 ms |
| 记录调用栈 | 关闭 | 定位资源、事件注册来源时按需开启；增加采集与上报开销 |

点击“应用设置并开始新会话”，在线预览在下一次配置查询后使用新设置。设置保存为项目 `extensions/cocos-performance-inspector/PITemp/capture-settings.json`，连接 Token 不写入文件。

低帧阈值默认 45 FPS、慢帧阈值 50 ms、堆趋势窗口 30 个采样。历史缓冲区默认最多 1800 个采样、2000 条资源事件、10000 条对象明细、10 个快照。达到上限会记录丢弃数量。

## 实时传输与面板

采集器按批次上传新增样本和资源事件，快照的对象与资源明细分块传输。每批带序号，收到编辑器确认后才推进发送位置；失败时重试原批次，编辑器按序去重。连接恢复或接收端丢失会话时，会重新同步运行时尚未淘汰的有界历史。

实时传输不在浏览器中周期性生成完整报告或执行整份报告分析。编辑器合并增量数据，面板只更新新增趋势数据和快照摘要；进入对象页时按需读取选中的快照，进入资源页时读取新增资源事件。

数据保存在编辑器内存中的当前会话。导出 HTML / JSON 时再组装完整报告并应用导出体积限制。已断开的预览可导出编辑器已收到的数据，尚未发送的数据在页面关闭或崩溃时可能丢失。

## 快照与报告

1. 完成资源预热，回到稳定业务界面，点击“拍摄快照”取得基线 A。
2. 重复打开 / 关闭或进入 / 返回同一功能至少三次。
3. 等待异步回调和延迟销毁，再在同一界面取得快照 B。
4. 比较 Node / Component、Tween、监听器、资源缓存与引用计数，并结合调用来源判断。

快照请求需等运行时轮询并完成分块传输，“已请求”不等于快照已出现。应先确认快照列表有新记录再导出，避免连续点击生成重复快照。启动时自动取得的快照可能没有场景，不应替代业务基线。

HTML / JSON 的导出目录固定为当前项目的 **`extensions/cocos-performance-inspector/PITemp`**，目录不存在时自动创建。导出不弹出保存位置选择框，每份报告使用唯一文件名，状态栏显示完整路径。

JSON 导入仍可选择任意报告文件，默认打开 PITemp。导入后重新校验与分析；离线报告不能请求运行时快照。HTML 完整转义项目数据，无外部脚本，可独立离线阅读。

## 性能与内存分析

- 在前台、可见的浏览器中执行相同操作；后台限帧、断点、CPU 限速和大量 Console 日志会影响结果。
- 区间 FPS、P95 和最大帧时反映观察到的引擎帧间隔，可能包含采集与序列化开销，不是 CPU 函数采样结果。
- 比较堆内存时，保持操作、时长和采集配置一致，关注正常回落后的低点。不同场景、资源预热和对象池会改变水位。
- 需要确认 JS 对象由谁持有时，用浏览器 Heap Snapshot 检查 Retainers；本插件不强制 GC，也不生成浏览器堆快照。
- 已销毁 Node / Component 仍被 WeakRef 观察到、已销毁 target 上仍有事件或 Tween，均需要结合生命周期和保留路径复核。
- 资源 load / release / addRef / decRef 表示观察到的 API 操作，不等于分配或回收了多少物理内存。
- 导出时原始 JSON 数据限制为 8 MiB UTF-8，超限会优先保留首尾快照与异常对象并说明截断；未保留数据不参与分析。HTML 还包含排版及转义后的内嵌数据，文件体积可能大于 8 MiB。

## 无数据时排查

1. 确认扩展目录直接位于 `项目/extensions/cocos-performance-inspector`，没有多套一层目录，并已在 Creator 启用。
2. 首次安装或替换扩展后刷新浏览器预览；检查面板是否有接收服务错误。
3. 使用 `http://localhost:预览端口` 或 `http://127.0.0.1:预览端口`，本版不自动接入局域网 IP、HTTPS、原生模拟器或真机。
4. 自定义预览模板应保留 Creator 原有的游戏初始化与插件加载逻辑。
5. 关闭或暂停页面后在线状态会过期，但已有报告仍可导出。

扩展停用后，自动入口在连续两次配置请求失败时停止 hooks 和采样；重新启用后自动重连。页面关闭时清理计时器和自动入口。删除或替换插件目录前，请备份其中 `PITemp` 内的报告与采集设置。

## 验收

| 场景 | 预期 |
| --- | --- |
| 干净项目只复制扩展 | 预览自动出现会话，assets 与场景无新增文件 |
| 刷新页面、切场景、重复加载脚本 | 每页一套采集，不重复 hooks；跨场景继续 |
| 改变采集配置 | 自动开始新会话，旧报告仍可查看 |
| 扩展重载 | 自动更新连接配置，无需复制 Token |
| 网络失败与重试 | 同一批次重复接收不增加样本、事件或快照 |
| 大快照 | 分块接收，完成后发布，后续实时上传复用已接收数据 |
| 面板轮询 | 只读取增量趋势与摘要，明细在对应页面按需加载 |
| 导出 HTML / JSON | 全部写入项目 `extensions/cocos-performance-inspector/PITemp`，无保存路径对话框 |
| 正式构建 | 不经过浏览器预览入口，不注入采集脚本 |
